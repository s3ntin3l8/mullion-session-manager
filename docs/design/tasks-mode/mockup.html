Tasks mode and Workspace mode — wireframes, rev 2

Proposal for #2976. Mullion gets two first-level modes: Workspace (the dockview grid, as today) and Tasks (the kanban board, front and center). These are low-fidelity wireframes: they show layout and flow, not final visuals. Each frame is drawn at its real size (desktop 1280, fold 840×900, phone 390) and scaled down. recommended marks the option I would pick; open marks a choice that needs your decision.

4 · Phone: where the mode switch goes decided: B

A bottom bar is the natural place for a two-way switch on a phone, but in Workspace mode the bottom edge belongs to the terminal key bar. Three ways to resolve it. All frames show Workspace mode with a terminal, the case where they differ; in Tasks mode there is no key bar, so every option can use the bottom bar of frame 3a.

5 · What changes, and what is still open

  • One task-detail surface per tier: the panel beside the board (desktop, fold), the pushed screen (phone). The sidebar detail and the docked TaskDetail panel go away.
  • One sidebar in both modes. Its Tasks view is a glance: rows, status, an in-place expansion with the main action, and "Open in Tasks".
  • Needs-you only on the mode switch. Running and finished tasks never light it.
  • Cross-links: task → "Open session in Workspace" → "← #7" chip back to the same task. PR chips and notifications that name a task open Tasks mode with it selected.
  • Phone navigator: its Tasks tab goes. What remains (Projects, Devices, Settings) needs its own rethink; not designed here.
  • The bell is unchanged here; its rework is #2985.
  • decidedPhone mode switch: B, the full-width bottom bar. Open detail: it hides while the on-screen keyboard is up.
  • openLeft sidebar and Dock in Tasks mode on desktop: hidden (as drawn), or kept?
  • openFold, task open: hide the right rail (as drawn) or keep it, so Git and PR for the task are one tap away?
  • open"Needs you" as the first lane on phone: it mixes statuses. The alternative is the plain status lanes plus the filter chip, as on desktop.
  • openAd-hoc sessions: still one collapsed strip under the board. Tapping one opens it in Workspace. Deeper integration is a later step.
  • openApprove from the sidebar glance: convenient, but it is an irreversible action on a small surface. Keep it, or make the glance read-only with "Open in Tasks"?
